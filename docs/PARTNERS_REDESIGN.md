# TaxPasso Partners: рабочий реестр и лист решений

База: `1f5268f`, ветка `design/partners-review-desk`. Изменения подготовлены для staging.

Пользователь — администратор или назначенный бухгалтер/агент. Его первый вопрос: на каком этапе заказ и какое решение ещё не подтверждено. Поэтому статус и предложение разделены визуально, а действия остаются рядом с анкетой.

## Токены и композиция

| Роль | Значение | Назначение |
|---|---|---|
| desk | #F3F6F8 | рабочая поверхность |
| paper | #FFFFFF | документы и формы |
| ink | #182D40 | заголовки и основной текст |
| action | #235B78 | действия и выбранный заказ |
| confirmed | #26715D | подтверждённые этапы |
| pending | #95621B | предложения, ожидающие решения |

Вспомогательные нейтрали: border #D5DFE5, secondary text #536779. Ошибки сохраняют красную семантику.
Inter, системный sans-serif при недоступности шрифта. Шкала: 28/600 заголовок заказа, 20/600 статус, 16/600 разделы и название в реестре, 14/400 текст, 12/500 пояснения. Табличные цифры используются для сумм и счётчиков.

| Область | Desktop | Mobile |
|---|---|---|
| Список заказов | Левая колонка 330px (280px на среднем экране), заголовок, вкладки, поиск, строки | Список сверху с ограниченной высотой, затем выбранный заказ |
| Карточка | Название; подтверждение и предложение в двух колонках; этапы; анкета и действия; документы, история | Все блоки последовательно; этапы вертикально |
| Финансы | Отдельная композиция AdminFinance внутри действий | Та же область на всю ширину |

Выравнивание по левому краю; таблицы анкеты имеют устойчивую колонку названий. Реестр разделён линиями, выбранная строка имеет вертикальную полосу. Пунктир и явные подписи отличают предложение от подтверждения даже без цвета.

## Проверка клише

Нет кремового фона, serif-заголовков, кислотного акцента, декоративных градиентов или теней под каждой секцией. Скругления различаются по назначению: документы 2px, поля 4px, диалог 8px. Нумерация остаётся только в последовательности этапов. Нет анимации появления каждой секции. Служебные заголовки приведены к обычному регистру; технические аббревиатуры сохранены.

## Реализация

- `src/components/OrderPresentation.tsx`: OrderLedgerEntry, ReviewState, AdminFinance. Компоненты не обращаются к Supabase.
- `src/main.tsx`: подключение компонентов, разметка, понятные пустые состояния. Tracker показывает подтверждённый статус, предложение показано отдельно. Это изменение отображения, не серверного состояния.
- `src/styles.css`: токены, реестр, лист решения, адаптивность, видимый focus, reduced motion.

Существующая версия использовала только светлую тему; она сохранена. Новая тёмная тема не добавлялась. RPC, параметры, обработчики бизнес-действий и загрузка данных сохранены. Финансовая область рендерится только для администратора; это не замена серверному контролю доступа.

## Проверки и ограничения

`npm run build` прошёл (TypeScript + Vite). Vite предупреждает о JS-бандле более 500kB. Подготовлен статический макет новых компонентов на искусственных данных без Supabase. Визуальная проверка не выполнена: Chromium отсутствует, загрузка браузера завершилась ошибкой повреждённого архива. Авторизованные экраны и права доступа в работающей системе не проверялись. AST-сравнение подтвердило неизменность всех 140 выражений вызова RPC/Supabase.

Перед выпуском: пройти реальный заказ под обеими ролями, консультацию специалиста, документы с длинными именами, журнал, финансовые формы и диалоги; проверить клавиатуру и масштаб 200%. Публикация разрешена только на staging; production не обновляется.

## Самокритика

Смелое решение — вынести двухключевую модель в крупный разделённый лист состояния. Формы и таблицы оставлены сдержанными, чтобы не увеличивать стоимость привычных действий. Характер несёт граница между сплошной подтверждённой областью и пунктирной областью предложения. Ограничение: существующая длинная карточка остаётся длинной; её разделение на рабочие вкладки потребует отдельного UX-решения.
